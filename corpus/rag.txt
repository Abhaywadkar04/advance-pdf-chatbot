Retrieval-Augmented Generation (RAG) is a technique that combines an information retrieval system with a large language model (LLM) to produce answers grounded in an external corpus of documents, rather than relying only on what the model memorized during training.

A basic RAG pipeline works in four stages:
1. Indexing — documents are split into chunks, converted into embeddings, and stored in a vector database (or alongside a keyword index).
2. Retrieval — when a user asks a question, the system finds the chunks most relevant to that question, either by keyword search (e.g. BM25), semantic vector search, or both combined (hybrid search).
3. Reranking (optional but common) — a smaller, more precise model called a cross-encoder re-scores the retrieved candidates by looking at the query and each chunk together, producing a more accurate relevance ranking than the initial retrieval step alone. The top few reranked chunks are kept.
4. Generation — the top-ranked chunks are inserted into the LLM's prompt as context, and the LLM generates a natural-language answer grounded in that context, often with citations back to the source chunks.

Combining BM25 (lexical/keyword search) with vector search (semantic search) is called hybrid search. The two methods are complementary: BM25 is strong at exact-term matches (names, codes, rare technical terms) but blind to synonyms and paraphrasing, while vector search captures meaning and handles paraphrased or loosely worded queries but can sometimes miss an exact rare term. The results from both legs are typically merged using Reciprocal Rank Fusion (RRF), which combines the rankings from each method into a single fused ranking without needing to normalize their raw scores.

The main benefit of RAG over relying on an LLM's built-in knowledge is that it reduces hallucination, allows the model to cite sources, and lets the system stay up to date or answer questions about private/internal documents without retraining the model.
